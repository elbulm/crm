# Протокол пилота партнёрского шаблона

## На пальцах

Цель пилота: проверить, может ли партнёр, ранее не работавший с этим сценарием, получить первый массовый прогон без обращения к автору шаблона.

Стартовый целевой норматив: 60 минут от получения двух Excel-файлов до начала первого массового прогона. До наблюдения владелец продукта может изменить число, но обязан записать его здесь и в журнале заранее.

Пилот считается успешным, если партнёр завершил полный цикл без подсказок автора. Наблюдатель фиксирует затруднения, но не обучает во время замера.

### Проверки результата

- [ ] DryRun понятен без документации ядра.
- [ ] Партнёр отличил RFP от SKU.
- [ ] Мастер правильно предложил обе колонки «Наименование».
- [ ] Партнёр исправил хотя бы одно неверное предложение эвристики самостоятельно.
- [ ] Категория настроена без редактирования отчёта.
- [ ] Партнёр объяснил две базовые части оценки.
- [ ] Принятое вручную решение пережило повторный прогон.
- [ ] Отклонённый кандидат не был предложен повторно.
- [ ] Excel и JSON содержат одинаковое число строк.
- [ ] Отключение ИИ не сломало ручной сценарий.

### Итоговая классификация

`configuration_only`: хватило мастера, конфига и гайда.

`template_change`: потребовалось изменить общий шаблон для поддерживаемого класса данных.

`custom_project`: данные или процесс вышли за явно описанную границу шаблона.

### Что внести в журнал

Запись содержит партнёра, категорию, начало, время первого прогона, минуты до прогона, число тикетов автору, признак изменения кода и заметки наблюдателя. Пример файла: `pilot-journal.example.json`.

После каждого пилота пересчитайте показатели одной командой из корня репозитория:

```text
node scripts/xcom-pilot-metrics.js docs/xcom-matching/pilot-journal.example.json
```

Расчёт выводит число и долю развёртываний без обращения к автору, медиану времени до первого прогона, долю развёртываний с изменением кода и соблюдение заранее заданной временной цели. Записи без корректной пары временных отметок перечисляются отдельно и не попадают в медиану.

## Грабли

- Не помогайте партнёру сразу: потеряется место реального затруднения.
- Не меняйте целевое время после старта пилота.
- Не называйте просьбу клиента кастомом только потому, что её неудобно параметризовать.
- Не добавляйте отраслевой пресет по одному случайному примеру. Сначала подтвердите повторяемость правила.
- Не считайте пилот успешным, если автор фактически управлял экраном или диктовал значения.
